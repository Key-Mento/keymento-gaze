# 👁️ keymento-gaze — 웹캠으로 화면 ↔ 건반 시선 전환 재기

[Keymento](https://github.com/Key-Mento/Keymento)(피아노 AR) 논문 실험용
도구. 전용 아이트래커 없이, 화면 위 웹캠으로 찍은 연주자 얼굴에서 **지금
화면을 보는지, 건반을 내려다보는지**만 가른다. 화면의 어느 지점을 보는지
(응시 지점)는 재지 않는다.

```
실험 전  run validate   신호음 검증 — 측정값이 실제로 내려다본 양에 비례하는가
실험 중  run record     얼굴 영상 + 프레임 시각 + 판정 이벤트 + 보정 구간 녹화
실험 후  run analyze    특징 추출 → 참가자별 보정 → 프레임 분류 → 지표·검증 결과
```

## Keymento 와의 관계

**실험에만 필요한 도구라 Keymento 와 저장소를 나눴다.**

- Keymento 코드를 불러오지도, 고치지도 않는다. 녹화기는 실행 중인 Keymento
  웹 UI 가 브라우저에 주는 상태(`http://127.0.0.1:8321/api/state`)를 똑같이
  읽어 판정 이벤트를 받을 뿐이다. 같은 PC 에서 Keymento 를 켜 두면 된다.
- 가상환경도 따로 쓴다(`.venv`). MediaPipe 가 설치하는
  `opencv-contrib-python` 이 Keymento 의 `opencv-python`(AR·ArUco)과
  충돌하기 때문이다.

판정 이벤트에는 발생 시각이 없어서, 녹화기가 "지난 폴링과 이번 폴링 사이의
가운데"로 어림한다. 연주 중에는 0.05초마다 물으므로 오차는 ±0.025초
안팎이다(`_events.jsonl` 의 `t_estimated`). 곡·모드·속도도 상태에서 읽어
`session` 줄을 직접 만든다.

## 🔧 준비 (한 번만)

이 저장소 폴더에서:

```powershell
git clone https://github.com/turn-world/keymento-gaze.git
cd keymento-gaze
run setup
```

가상환경을 만들고 MediaPipe 를 설치한다. 얼굴 모델(`face_landmarker.task`,
약 3.6MB)은 처음 쓸 때 `models\`에 자동으로 받는다.

### 카메라 배치

- 참가자가 보는 화면(AR 화면 또는 악보 화면) **바로 위**에 얼굴 카메라를
  두고 얼굴을 정면에서 찍는다.
- **Keymento AR 이 쓰는 카메라와 다른 번호**여야 한다. AR 은 1번을 먼저
  쓰므로 노트북 내장 카메라(보통 0번)가 기본값이다. 다르면 `--camera N`.
- 얼굴이 어둡지 않게 앞쪽 조명을 둔다. 안경은 메모해 둔다(`--note "안경"`).
- 두 조건 모두 **같은 화면, 같은 카메라 위치**를 써야 비교가 공정하다.

## ✅ 검증 — 측정이 실제 행동에 비례하는가 (참가자마다 약 3분)

측정값이 정확히 맞을 필요는 없지만, **실제로 많이 내려다보면 측정값도 그만큼
커져야** 조건 비교가 의미가 있다. 이를 보이려고 정답을 아는 상황을 만든다.

```powershell
run validate --participant P01
```

1. 참가자에게 알려 준다: **"높은 삐 = 건반을 내려다보기, 낮은 삐 = 화면으로
   돌아오기."** (보정 신호도 같은 규칙: 높은 음은 건반, 낮은 음은 화면)
2. 미리보기 창에서 **V**. 보정(10초)이 먼저 돌고 이어서 검증이 시작된다.
3. 블록 3개 × 50초. 블록마다 내려다보는 횟수가 4·8·12회(순서 무작위),
   한 번에 0.5~2.5초. 시점은 무작위다.
4. 끝나면 길게 삐- 한다. **ESC** 로 저장.

분석하면(`run analyze`) 이렇게 나온다:

```
[검증] 신호 24개 중 23개 검출 (95.8%) · 거짓 내려다봄 0.4회/분 · 반응 지연 0.52초(중앙값)
   시간 비례 (신호 24개): r = 0.93 · 기울기 0.98 · 절편 0.05초
   블록별 지시 → 측정: 4회/6.1초 → 4회/5.8초 · 12회/18.0초 → 11회/17.2초 · ...
```

(숫자는 예시다.) 참가자를 여러 명 하면 마지막에 **검증 종합**으로 신호·블록을
모두 모은 r·기울기가 나온다 — 논문에는 이 값을 쓴다.

| 값 | 뜻 | 좋은 값 |
|---|---|---|
| 검출률 | 신호를 따라 내려다본 것이 잡힌 비율 | 높을수록 |
| 거짓 내려다봄 | 신호 없이 잡힌 내려다봄 (분당) | 0 에 가까울수록 |
| 반응 지연 | 신호부터 '건반'으로 바뀌기까지 (사람 반응 시간 포함) | 0.3~0.7초면 정상 |
| 시간 비례 | 지시한 내려다봄 시간 ↔ 측정 시간 (신호마다) | r 이 1, 기울기 1, 절편 0 에 가까울수록 |
| 횟수 비례 | 지시한 횟수 ↔ 측정 횟수 (블록마다) | 〃 |
| 총 시간 비례 | 지시한 총 시간 ↔ 측정 총 시간 (블록마다) | 〃 |

> 논문 문장 예: "지시한 내려다봄 시간과 측정 시간의 상관은 r = .9x(기울기 0.9x)
> 였다." 횟수와 시간 중 더 잘 비례하는 쪽을 주 지표로 정한다.

## 🧪 본 실험 (참가자 한 명, 조건 하나)

1. Keymento 를 켠다 (Keymento 폴더에서).
   - AR 조건: `run`
   - 악보 조건: `run nocam` + 같은 모니터에 악보 이미지 전체 화면
   - 웹 UI 는 실험자만 본다 (다음 목표 음이 나오므로).
2. 녹화기를 켠다 (이 저장소 폴더에서).

   ```powershell
   run record --participant P01 --condition AR
   ```

   미리보기에서 얼굴에 **초록 상자**가 뜨는지, 아래에 `APP: idle` 이
   보이는지(Keymento 와 연결됨) 확인한다.
3. 참가자에게 알려 준다: **"삐 한 번이면 화면 가운데, 삐삐면 손을 건반에
   올리고 칠 때처럼 건반을 보세요, 길게 삐- 하면 끝입니다."**
   - 건반을 볼 때 고개를 숙이는 사람도, 눈만 내리는 사람도 있다. 보정
     자세가 실제 연주 자세와 같아야 그 사람의 방식이 기준에 담긴다.
4. **C** 를 누른다. 녹화가 시작되고 보정(화면 5초 → 건반 5초)이 진행된다.
   잘못됐으면 C 를 다시 누르면 된다 — 분석은 각 시점에 그 직전 보정을 쓴다.
5. 웹 UI 에서 연주를 시작한다. 판정 이벤트는 녹화기가 알아서 받는다.
6. 끝나면 **ESC**. 다음 조건은 1번부터 다시 한다.

> 녹화를 **먼저** 시작하고 연주를 시작한다. 연주 도중에 녹화를 켜면 그
> 시도는 앞부분이 빠진다.

| 키 | 동작 |
|---|---|
| `R` | 녹화 시작 |
| `C` | 보정 (녹화 전이면 녹화도 함께 시작) |
| `V` | 검증 (보정 전이면 보정부터) |
| `ESC` / `Q` | 저장하고 종료 |

녹화는 `data\P01\` 에 모인다. **참가자 얼굴이 담긴 개인정보라 `data\` 는
git 에서 제외해 두었다**(`.gitignore`). 외부에 올리지 않는다.

## 📊 분석

```powershell
run analyze                                   data\ 아래 녹화 전부
run analyze data\P01                          한 참가자
run analyze data\P01\P01_AR_..._meta.json --review     확인용 영상까지
```

시작할 때 MediaPipe 가 `WARNING: Logging before InitGoogle()` 같은 줄을
몇 줄 찍는데, 정상이다.

### 결과 파일

| 파일 | 내용 |
|---|---|
| `data\results.csv` | **참가자 × 조건 × 시도마다 한 줄** — 통계에 바로 쓰는 표 |
| `data\validation.csv` | 모든 검증 신호 (지시 시간·측정 시간·검출·지연) |
| `data\validation_blocks.csv` | 모든 검증 블록 (지시 횟수·시간 ↔ 측정) |
| `..._notes.csv` | 음(걸음)별 소요 시간·오타와 그 사이의 시선 |
| `..._validation.csv` | 그 녹화의 검증 신호 |
| `..._gaze.csv` | 프레임별 점수(0=화면 자세 ~ 1=건반 자세)와 상태 |
| `..._calibration.json` | 이 녹화에 쓴 판별 기준·임계값 |
| `..._features.csv` | 프레임별 얼굴 특징 (다시 돌리면 재사용, `--force` 로 새로) |
| `..._review.mp4` | `--review` — 분류 결과를 얹은 확인용 영상 |

### `results.csv` 주요 열

| 열 | 뜻 |
|---|---|
| `screen_ratio` | 화면을 본 시간 비율 (판별된 시간 기준) |
| `glances` | 화면 → 건반 전환 횟수 (내려다본 횟수) |
| `glances_per_min` | 분당 내려다본 횟수 |
| `keys_dwell_mean_s` | 한 번 내려다볼 때 머문 평균 시간(초) |
| `valid_ratio` | 시선을 판별한 시간 비율 — 낮으면 카메라·조명 확인 |
| `face_ratio` | 얼굴이 잡힌 프레임 비율 |
| `steps_looked_down_ratio` | 건반을 내려다보며 친 음의 비율 |
| `note_time_median_s` | 음당 소요 시간 중앙값 (연습 모드) |
| `wrong_presses` | 오타 수 |
| `pitch_accuracy`, `timing_accuracy`, `overall` | 판정 결과 (완주한 시도만) |
| `calib_separation` | 보정 분리도 d' — 3 이상 좋음, 2 미만이면 의심 |

시도 하나는 웹 UI 에서 연주를 시작한 때부터 완주·중단까지다(카운트다운
제외). 판정 이벤트가 없으면 녹화에서 보정·검증 구간을 뺀 나머지 중 5초 이상인
구간을 각각 한 시도로 본다(`status = no-events`). 콘솔에 `녹화 23.1~65.8초`
처럼 구간이 찍히므로 확인용 영상과 맞춰 볼 수 있다.

### 자주 쓰는 옵션

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--review` | — | 확인용 영상 만들기 |
| `--calib-from META` | — | 보정을 빠뜨린 녹화를 같은 참가자의 다른 녹화 보정으로 분석. 두 조건에 **같은 기준**을 쓰고 싶을 때도 쓴다 |
| `--calib-trim` | `1.0` | 보정 구간 앞에서 버릴 초 (신호를 듣고 시선을 옮기는 시간) |
| `--enter` / `--leave` | `0.6` / `0.4` | 화면→건반 / 건반→화면으로 바뀌는 점수 |
| `--min-duration` | `0.2` | 이보다 짧은 시선 구간은 흡수(초) |
| `--max-gap` | `0.5` | 이보다 짧게 얼굴을 놓친 구간은 앞 상태로 메움(초) |

## 🧠 분류 방법 (논문 방법 절에 옮겨 쓸 수 있게)

1. **특징 추출** — MediaPipe Face Landmarker 로 프레임마다 얼굴 랜드마크
   478점, blendshape 52개, 얼굴 변환 행렬을 얻고 네 값을 뽑는다.
   - 머리 끄덕임 각도(pitch)
   - 눈동자 아래 보기 정도 (`eyeLookDown − eyeLookUp`, 양 눈 평균)
   - 눈꼬리 선 대비 홍채 중심의 높이 (눈 너비로 정규화)
   - 눈꺼풀 사이 간격 (눈 너비로 정규화 — 내려다보면 좁아진다)
2. **참가자별 보정** — 녹화마다 화면 응시 5초, 건반 응시 5초를 기록한다.
   각 구간의 처음 1초를 버리고, 깜빡임과 이상치를 뺀 뒤, 두 자세를 가장 잘
   가르는 선형 판별 방향(LDA)을 구한다. 모든 프레임을 이 축에 투영해
   화면 자세 평균이 0, 건반 자세 평균이 1 이 되는 점수로 바꾼다. 보정을
   여러 번 했으면 각 시점에는 그 직전 보정을 쓴다.
3. **깜빡임** — 눈꺼풀이 거의 덮인 상태가 0.25초 미만이면 깜빡임으로 보고
   앞 상태로 메운다. 더 길면 깊게 내려다본 것으로 보고 그대로 판정한다
   (건반을 깊이 내려다보면 눈꺼풀이 덮여 깜빡임과 모양이 같아진다).
4. **상태 결정** — 이력 임계값(화면→건반 0.6, 건반→화면 0.4)으로 경계
   근처의 떨림을 막는다. 0.5초 미만의 얼굴 놓침은 앞 상태로 메우고,
   0.2초 미만의 구간은 이웃 구간에 흡수한다. 0.5초 이상 얼굴을 놓친 구간은
   '알 수 없음'으로 두고 비율 계산에서 뺀다.
5. **시간 맞춤** — 영상 프레임 시각과 판정 이벤트 시각을 같은 PC 시계로
   기록해, 시도 구간과 음별 구간에 시선 상태를 붙인다.
6. **검증** — 무작위 신호음으로 내려다볼 시점·시간을 지시하고(블록마다
   4·8·12회, 0.5~2.5초), 지시값과 측정값의 상관·기울기로 비례성을 보인다.

### 한계

- 응시 지점이 아니라 **방향(화면/건반)만** 판별한다. AR 화면 안에서 HUD 를
  봤는지 건반 오버레이를 봤는지는 알 수 없다.
- 참가자별 보정에 의존한다. 보정 자세(고개를 숙이는지, 눈만 내리는지)에
  따라 애매한 시선의 판정이 달라질 수 있다 — `calib_separation`, 검증
  결과, `--review` 영상으로 확인한다.
- 판정 이벤트 시각은 폴링으로 어림한 값이다(±0.025초 안팎).

## 🧩 구성

```
keymento-gaze/
├── run.bat            setup · record · validate · analyze · test
├── requirements.txt   mediapipe (numpy·opencv-contrib 포함)
├── gaze/
│   ├── record_face.py 녹화기 — 미리보기·보정/검증 신호음·이벤트 수신
│   ├── analyze.py     분석 — 결과 CSV·검증 결과·확인용 영상
│   ├── validation.py  신호음 검증 — 일정·신호 내기·정답과 비교
│   ├── features.py    MediaPipe 특징 추출
│   ├── classify.py    보정(LDA)·프레임 분류 — numpy 만
│   ├── metrics.py     시도 나누기·시선 지표·음별 표
│   └── recording.py   녹화 파일 이름·메타 정보
├── tests/test_gaze.py 단위 테스트 (run test)
├── data/              녹화 — git 제외
├── models/            얼굴 모델 — git 제외, 자동 다운로드
└── .venv/             실험 도구 venv — git 제외
```
